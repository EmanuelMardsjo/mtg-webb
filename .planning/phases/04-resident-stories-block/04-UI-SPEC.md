# Phase 4 — UI Design Contract

> Visual and interaction contract for the **Resident Stories block** (`ResidentStories`). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is an ADAPTATION phase, not greenfield, and it is the heaviest-interaction block in the milestone.** The visual + interaction direction is already decided by the source design exploration (`design-import/claude-design/MTG-blocks/mtg-story.{js,css}` + the `.stories` markup in `Move to Gothenburg.html`). This contract maps that sticky scroll-driven story sequence onto the token-driven React design system — it does **not** re-invent the look, does **not** add new tokens or a new palette (hard constraint: PROJECT.md REQ-02 + brand guardrails), and does **not** recreate the source's bespoke manual scroll-math / scroll-jacking. It follows the idiom proven by the shipped Phase 1 (`FeatureSpotlight`), Phase 2 (`FooterCta`), and Phase 3 (`CrashCourseRail`) blocks, and — critically — the **closest existing analog, `MTGNeighborhoods`**, which already implements exactly this pattern: a `position: sticky` stage + a tall full-viewport-anchor track + `useScrollSections` deriving an active index, degrading to a static stack.

### Source Disambiguation (read before implementing)

The source `mtg-story.js` is a *superset*: it contains (a) the sticky cross-fading story sequence with a progress fill, (b) a custom ghost-button cursor, and (c) a full editorial drawer. **This phase's scope is (a) only** — ROADMAP Phase 4 goal: "a sticky scroll-driven story sequence with a progress fill indicator," SC#1 "a sticky-stories block … with full folder anatomy," SC#2 "scroll-driven progression works and **degrades gracefully** under `prefers-reduced-motion`," SC#3 "reuses scroll hooks where possible." The ghost cursor (b, D-6) and drawer (c, D-7) are de-scoped. This is faithful to the source's enduring idea ("one continuous pin → resident stories cross-fade through a single viewport, degrading to a static stack"), not a deviation. **Crucially**, the source itself ships the static stack as its no-JS/reduced-motion contract — we render that stack as the accessibility baseline and layer the sticky behavior on top only when JS runs AND motion is allowed.

**`ResidentStoriesContent` shape (D-8 — intro heading is optional, see flag):**

```ts
import type { ThemeName } from '@tokens/themes'

export type ResidentStory = {
  eyebrow: string                  // origin → destination, e.g. "Bangalore → Lindholmen"
  headline: string                 // the pulled quote, e.g. "A forest twelve minutes from work." (renders as the story heading; supports \n)
  attribution: string              // "Aditi Menon — Staff engineer, Volvo Cars · arrived 2022 with partner & daughter"
  attributionName?: string         // OPTIONAL — the bold lead of the attribution ("Aditi Menon") if the author wants it emphasized separately from the role/detail
  image: { src: string; alt: string }   // alt required by the Image primitive
  side?: 'left' | 'right'          // OPTIONAL — which side the media sits (source alternates right/left/right). Default: alternate by index.
  href?: string                    // OPTIONAL (D-7). With href → the story is a navigating <a>; without → a non-interactive <article>.
}

export type ResidentStoriesContent = {
  eyebrow?: string                 // OPTIONAL intro eyebrow for the whole block (source has none — see D-8)
  heading?: string                 // OPTIONAL intro heading for the whole block (source has none; the section aria-label is the source's "Stories from people who made the move") — see D-8
  stories: ResidentStory[]         // source ships 3 (Aditi, Tomás, Maya)
  theme?: ThemeName                // default 'pink-soft' (the warm pink field). Local to the Section.
}
```

**Composition (target idiom — follows `MTGNeighborhoods` sticky-stage + track pattern):**

```
<Section theme={content.theme ?? 'pink-soft'} spacing="sm"
         aria-label={content.heading ?? 'Stories from people who made the move'}>
  <div className={s.block}>

    {/* ---- sticky stage: one viewport every story shares ---- */}
    <div className={s.stage}>
      {/* progress indicator — decorative by default (D-4) */}
      <div className={s.progress} aria-hidden
           style={{ ['--progress' as string]: (activeIndex + 1) / stories.length }}>
        <span className={s.progressFill} />
      </div>

      {stories.map((story, i) => {
        const isActive = ids[i] === activeId
        const Tag = story.href ? 'a' : 'article'
        return (
          <Tag key={i} href={story.href}
               className={[s.story, isActive && s.storyActive].filter(Boolean).join(' ')}
               data-side={story.side ?? (i % 2 ? 'left' : 'right')}>
            <div className={s.inner}>
              <div className={s.text}>
                <div className={s.rise} style={riseStyle(0)}>   <Text role="tag">{story.eyebrow}</Text> </div>
                <div className={s.quote}>
                  <span className={s.mark} aria-hidden>{/* giant " */}</span>
                  <div className={s.rise} style={riseStyle(90)}> <Text role="h3" as="h3">{story.headline}</Text> </div>
                </div>
                <div className={s.rise} style={riseStyle(180)}> <Text role="body" as="p">{story.attribution}</Text> </div>
                {story.href && <span className={s.more}>Read story <Icon name="arrow-right" size="sm" aria-hidden /></span>}
              </div>
              <figure className={s.media}>
                <Image src={story.image.src} alt={story.image.alt} focalPoint="center" loading="lazy" />
              </figure>
            </div>
          </Tag>
        )
      })}
    </div>

    {/* ---- tall scroll track: one full viewport per story drives activeId ---- */}
    <div className={s.track} aria-hidden>
      {stories.map((story, i) => (
        <div key={i} ref={register(ids[i])} className={s.anchor} />
      ))}
    </div>

  </div>
</Section>
```

## Spacing Scale

The DS spacing scale is fixed by `src/tokens/primitives/space.ts` (base 4px, 8-point family) and consumed only through `src/tokens/semantic/space.ts` **semantic** roles — never raw values, never `space[N]` directly.

| Token (CSS var) | Resolves to | Usage in this block |
|-------|-------|-------|
| `--space-5` | 24px (`space[5]`) | Stage gutter: `.block` `padding-inline: var(--space-5)`; stage `top: var(--space-5)`; stage `height: calc(100vh - 2 * var(--space-5))` — **the exact `MTGNeighborhoods` analog gutter** |
| `--space-stack-loose` | 24px (`space[5]`) | Text column rhythm (eyebrow → quote → attribution) — source `.story__text gap: var(--space-stack-loose)` (exact) |
| `--space-content-gap` | 32px (`space[6]`) | Text column ↔ media gap on the smaller end (source `.story__inner gap: clamp(32px,5vw,110px)` — the clamp collapses to a `content-gap` floor stepping up to `--space-stack-2xl`/larger on wide viewports) |
| `--space-stack-default` | 16px (`space[4]`) | Stacked-fallback inner gaps; "Read story" affordance vertical offset |
| `--space-inline-default` | 8px | "Read story" label → arrow gap (source `.ccx__more`-style affordance) |
| `--space-section-y-md` | 96px | Static-stack fallback story `padding-block` (source `.stories:not(.is-live) .story padding-block: var(--space-section-y-md)` — exact) |
| `--space-container-pad-{sm,md,lg}` | 16 / 32 / 64px | (Not via Container here.) The `story__inner` cap is `width: min(1180px, 90vw)` (source) in block CSS |

**Stage/track dimensions** (`100vh` viewport, `calc(100vh - 2*--space-5)` stage height, `100vh` per anchor, `min(1180px,90vw)` inner cap, `max-width:460px` media) are **layout values**, not spacing-scale gaps — expressed with `vh`/`min()`/`calc()` in block-local CSS (the `MTGNeighborhoods` precedent). The 8-point scale governs gaps/padding/rhythm only.

**Radius** is **not** a spacing value: stage + media radius via `calc(var(--radius-lg) * 1.5)` (≈24px, the source `--card-radius` intent); progress rail radius `var(--radius-pill)` (source used `--radius-full` on a 3px bar — `--radius-pill` 9999px is the correct "fully rounded bar" token, `--radius-full` 50% is for circles).

Exceptions: **none.** All gaps/padding/rhythm flow through existing semantic space tokens. Source `clamp()` fluid spacing collapses to discrete DS tokens with sm/md/lg responsive steps — the faithful DS-native expression.

## Motion (REQ-04 — ACCESSIBILITY + graceful degradation are success criteria, SC#2)

| Behavior | Source | This contract |
|---|---|---|
| **Sticky pin + global progress** | `position: sticky` pin in a `440vh` track; JS computes `G` from `-r.top/travel` per scroll frame and cross-fades stories on overlapping windows | **PORTED via the `MTGNeighborhoods` pattern (D-2).** Block-local sticky **stage** (`top: var(--space-5); height: calc(100vh - 2*--space-5); overflow:hidden`) inside a tall **track** of N × `100vh` anchors. `useScrollSections` derives `activeId` (IntersectionObserver at the viewport mid-line — **no scroll-jacking, no manual scroll math, no per-frame DOM writes**). Active story gets `is-active`; others are `opacity:0 / pointer-events:none`. **Cross-fade via CSS `transition` on `opacity`** keyed off `is-active` (token-timed). |
| **Per-piece text rise** | Each `.story__piece` rises piece-by-piece on `cubic-bezier(0.16,1,0.3,1)`, scroll-coupled, holds, lifts out | **Restrained single staggered rise** when a story becomes active: `.rise` pieces (eyebrow 0ms → headline 90ms → attribution 180ms) translate + fade in on the `is-active` transition, using `--motion-reveal-duration`/`--motion-reveal-easing` (the established Phases 1–3 `.rise` + `--rise-d` mechanism). **No continuous scroll-coupled `translate3d` recompute.** Honors restrained-motion guardrail. |
| **Image parallax (210px)** | Deep `IMG_AMP 210px` parallax smoothed by a CSS transition | **Cross-fade in only** (opacity + small `.rise` translateY). Optional restrained `useParallax` drift on the active media (D-5) — small magnitude, off by default, reduced-motion-guarded. The 210px travel is **dropped** (off-brand magnitude). |
| **Progress fill** | `progressFill.style.height = G*100%` every frame; rail `is-visible` toggled by viewport-mid intersection | `transform: scaleY(var(--progress))` where `--progress = (activeIndex + 1) / N`, set as an inline CSS var (no per-frame JS height writes). `transform-origin: top`. Token-timed transition. **Decorative `aria-hidden` by default** (D-4). Hidden under reduced-motion + in the static-stack fallback. |
| **Smooth scroll on jump** | n/a (no jump UI in source for this block) | If a "jump to story" affordance is added later, use `useScrollSections` `scrollTo` (already `behavior: reduced ? 'auto' : 'smooth'`). Not in v1 scope. |
| Ghost cursor | custom blurred follow-cursor | **DROPPED (D-6).** No DS precedent; replaces native cursor (a11y/low-chrome violation). |
| **Reduced motion / no-JS** | `.stories:not(.is-live)` → track `height:auto`, pin `position:static`, stories `position:relative; min-height:100vh; padding-block` → **fully visible static stack**; progress `display:none` | **PRESERVED as canonical fallback + SC#2.** Block CSS `@media (prefers-reduced-motion: reduce)`: stage `position:static; height:auto; overflow:visible`; track `height:auto`; stories `position:relative; inset:auto; opacity:1; min-height:auto; padding-block: var(--space-section-y-md)`; `.rise`/media `transition:none; transform:none; opacity:1`; progress `display:none`. **All stories fully visible, statically stacked, normally scrollable, no pinning, no scroll-coupling.** `useScrollSections` still merely *observes* (no scroll-jacking) and `scrollTo` would be `auto` — but with the static stack there is nothing to drive. **Required by REQ-04 + SC#2.** |

No `useReveal` (the `is-active` class drives the rise). No bespoke scroll listener (that is `useScrollSections`' job).

## Interaction & Accessibility Notes (SC#2 — the binding success criterion)

- **Sticky stage:** block-local `<div className={s.stage}>` — `position: sticky; top: var(--space-5); height: calc(100vh - 2*var(--space-5)); overflow: hidden; border-radius: calc(var(--radius-lg)*1.5)` (the `MTGNeighborhoods` analog). It must NOT be wrapped in `Container` (would constrain the full-viewport stage). The stage contains all story panels (absolutely positioned, cross-faded) + the progress indicator.
- **Track:** `<div className={s.track} aria-hidden>` — a flex column of N × `100vh` `.anchor` divs, each registered via `useScrollSections` `register(ids[i])`. `aria-hidden` because the anchors are pure scroll-distance scaffolding (the `MTGNeighborhoods` precedent); the readable content lives in the stage panels.
- **Stories are real articles (SC#1 anatomy):** each story is an `<article>` (or `<a>` when `href`) containing an eyebrow, an **`<h3>` headline** (the pulled quote, a real heading so the block has a navigable outline: block `aria-label` → story `h3`s), and an attribution paragraph. **No `role="button"` + `tabindex` on a div** (the source did this for the drawer — dropped). When `story.href`: the whole panel is an `<a>` (natural tab stop, `Enter` activates) with a visible "Read story" affordance; without `href`: a non-interactive `<article>` (no `tabindex`, no dead click).
- **Focus order:** Section → (each linked story `<a>` in DOM order, if any) → next block. The progress indicator is not focusable (decorative). The track anchors are `aria-hidden` and not focusable. In the **static-stack fallback** focus order is simply each story in DOM order — fully keyboard reachable, which is the point of SC#2.
- **Progress indicator semantics (D-4):** **default `aria-hidden`** — it visualizes scroll position, which AT users already get from heading order + normal reading flow; an `aria-valuenow` that updates on every scroll would be noisy. **Enhancement option:** expose `role="progressbar"` `aria-valuemin={1} aria-valuemax={N} aria-valuenow={activeIndex+1}` `aria-label="Story {activeIndex+1} of {N}"` if a sequence position is judged genuinely useful to AT. Recommendation: ship `aria-hidden`, flag the `progressbar` option.
- **Accessibility — Section labelling:** `aria-label` on the `Section` (source `.stories aria-label="Stories from people who made the move"`; or `content.heading` if provided). `Text` exposes no `id`, so `aria-labelledby` is not wired (Phases 1–3 precedent). Story headlines are real `<h3>`s. Image `alt` required by the `Image` primitive (each portrait has a meaningful alt). The decorative giant quote `"` is `aria-hidden`.
- **The sequence must be fully readable WITHOUT scroll-JS:** if JS never runs (`useScrollSections` no-ops without `IntersectionObserver`/`window`), the CSS static-stack fallback must already present all stories visibly. Therefore the **base CSS state of every `.story` is fully visible** (`opacity:1`); the sticky absolute-overlap + cross-fade hidden states apply **only** under an `is-live`-style guard (e.g. a `data-live` attribute the component sets in an effect after mount, mirroring the source `.is-live` gate, OR scoping the absolute/hidden styles so they require JS-applied classes). This guarantees no-JS = readable stack. **This is the SC#2 contract.**
- **Reduced motion:** static stack, all stories visible, no pinning, no cross-fade, no rise, progress hidden. `useScrollSections` `scrollTo` (if ever invoked) is `auto`. No scroll-coupling whatsoever.
- **Responsive:** under 760px the source drops the progress rail and stacks the `story__inner` to a single centered column (media first, `order:-1`), text centered. Preserve: media-on-top single column under ~760px; progress `display:none` under 760px; consider letting the whole block fall to the static stack under a small breakpoint (the sticky one-viewport-per-story interaction is most meaningful on larger screens — `MTGNeighborhoods` does exactly this, switching to an in-flow stage under 768px). Recommendation: below 768px, render the static stack (D-2 note).
