<objective>
Create the content type and the `ResidentStories` React component — the sticky scroll-driven resident-story sequence. The component composes a `Section theme="pink-soft"`, a block-local sticky **stage** (containing the decorative progress indicator and all story panels, cross-faded by an `storyActive` class), and a tall `aria-hidden` **track** of one full-viewport anchor per story registered via `useScrollSections`. It holds NO manual scroll machinery — `useScrollSections` (the proven `MTGNeighborhoods` reuse, D-2) derives the active story index, which drives both the `storyActive` class and the inline `--progress` CSS var. Critically, it sets a post-mount **`data-live` gate** on the block root (the React-idiomatic equivalent of the source's `.is-live` class, UI-SPEC line ~267): only after JS mounts does `data-live` appear, which is what 04-02's CSS uses to switch on the absolute cross-fade hidden states. Pre-mount / no-JS, no `data-live` → the base state stays a readable in-flow stack (SC#2).

Purpose: Establishes the block anatomy (REQ-01, REQ-03), the scroll-hook reuse (REQ-04, SC#3), and the no-JS-readable structure with its `data-live` gate (SC#2). The CSS that turns this structure into a sticky cross-fading sequence — plus the story, test, and barrel — lands in 04-02.

Output: `types.ts` and `ResidentStories.tsx`. (Until 04-02 adds the CSS module, story, and barrel, this plan's `npm run typecheck` will fail on the missing `./ResidentStories.module.css` import — see Task 2 note; lint/typecheck of the full block is gated in 04-02.)
</objective>
