# Phase 3 — UI Design Contract

> Visual and interaction contract for the **Crash Course block** (`CrashCourseRail`, variant **C** — "tram window: scroll the strip"). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is an ADAPTATION phase, not greenfield.** The visual + interaction direction is already decided by the marked-final source exploration (`design-import/claude-design/MTG-blocks/Crash Course - C.html` + `crash-c.css` + `crash-c.js`). This contract maps that look onto the token-driven React design system — it does not re-invent it, and it does not add new tokens or a new palette (hard constraint: PROJECT.md REQ-02 + brand guardrails). It follows the idiom proven by the shipped Phase 1 (`FeatureSpotlight`) and Phase 2 (`FooterCta`) blocks, and the closest existing analog `MTGNeighborhoods` (cards + button-per-item paginator with `aria-current`).

The block is **image-led, whitespace-heavy, low-chrome, one editorial header → one scrollable strip** — aligned with the premium-editorial guardrails (narrative "local friend pointing at the good stuff," not a dashboard grid). Faithful adaptation requires no art-direction deviation.

### Source Disambiguation (read before implementing)

The source file is a *superset*: it contains (a) a scroll-snap rail, (b) an "Explore" deck-fan reveal animation gating that rail, and (c) a full editorial drawer. **Variant C's enduring contribution — and this phase's scope — is the rail with dots + keyboard nav** (ROADMAP Phase 3 goal + success criteria). The deck-fan reveal (b) and drawer (c) are explicitly de-scoped here (D-3, D-4) and are consistent with how the source *itself* degrades (its reduced-motion path is exactly the static rail). This is faithful to variant C's core idea ("the tram window — scroll the strip"), not a deviation.

**`CrashCourseRailContent` shape:**

```ts
import type { ThemeName } from '@tokens/themes'

export type CrashCourseRailCard = {
  title: string                    // "Fika"
  description: string              // the card body copy (≤ ~3 lines on the card)
  image: { src: string; alt: string }   // alt required by the Image primitive
  href?: string                    // OPTIONAL (D-4). With href → card is a navigating <a>.
                                   // Without → card is a non-interactive <article> (no dead click).
}

export type CrashCourseRailContent = {
  eyebrow?: string                 // OPTIONAL — source header is heading+lead only; eyebrow kept for parity with sibling blocks
  heading: string                  // "A crash course in Gothenburg life"; supports \n / string[] lines
  lead?: string                    // supporting paragraph, ≤ ~54ch (source max-width: 54ch)
  cards: CrashCourseRailCard[]     // source ships 8
  theme?: ThemeName                // default 'yellow' (the #FFFD8C field). Local to the Section.
}
```

**Composition (target idiom — follows `FooterCta` + `MTGNeighborhoods` paginator):**

```
<Section theme={content.theme ?? 'yellow'} spacing="lg" aria-label={content.heading}>
  <Container size="default">

    {/* ---- editorial header (centered) ---- */}
    <Stack gap="loose" align="center" className={s.head}>      ← max-width ~60ch, centered
      {content.eyebrow && <div className={s.rise} style={riseStyle(0)}><Text role="tag">{eyebrow}</Text></div>}
      <div className={s.rise} style={riseStyle(90)}><Text role="display" as="h2">{heading}</Text></div>
      {content.lead && <div className={s.rise} style={riseStyle(180)}><Text role="lead">{lead}</Text></div>}
    </Stack>

    {/* ---- scroll-snap rail ---- */}
    <ul ref={railRef} className={s.rail} aria-label={`${heading} — scrollable cards`}>   ← role="list" implicit; tabIndex={0} so the region is focusable for arrow-key scroll
      {cards.map((card, i) => (
        <li key={i} className={s.cell}>
          {Tag = card.href ? 'a' : 'article'}
          <Tag href={card.href} className={s.card}>
            <figure className={s.media}>
              <Image src alt focalPoint="center" loading="lazy" />     ← fills figure, object-fit cover
            </figure>
            <span className={s.cap}>                                   ← gradient sits between media and cap
              <Text role="h3" as="span" className={s.cardTitle}>{card.title}</Text>
              <Text role="body-sm" as="span" className={s.cardDesc}>{card.description}</Text>
              {card.href && (
                <span className={s.more}>Read more <Icon name="arrow-right" size="sm" aria-hidden /></span>
              )}
            </span>
          </Tag>
        </li>
      ))}
    </ul>

    {/* ---- control row: dots + prev/next ---- */}
    <div className={s.controls}>
      <nav className={s.dots} aria-label="Crash course pagination">
        {cards.map((card, i) => (
          <button type="button" key={i}
                  className={[s.dot, i === activeIndex && s.dotActive].filter(Boolean).join(' ')}
                  aria-current={i === activeIndex ? 'true' : undefined}
                  aria-label={`Go to ${card.title}`}
                  onClick={() => scrollToIndex(i)} />
        ))}
      </nav>
      <div className={s.nav}>
        <button type="button" className={s.navBtn} aria-label="Previous"
                disabled={activeIndex === 0} onClick={() => scrollToIndex(activeIndex - 1)}>
          <svg aria-hidden …chevron-left… />
        </button>
        <button type="button" className={s.navBtn} aria-label="Next"
                disabled={activeIndex === cards.length - 1} onClick={() => scrollToIndex(activeIndex + 1)}>
          <svg aria-hidden …chevron-right… />
        </button>
      </div>
    </div>

  </Container>
</Section>
```

## Spacing Scale

The DS spacing scale is fixed by `src/tokens/primitives/space.ts` (base 4px, 8-point family) and consumed only through `src/tokens/semantic/space.ts` **semantic** roles — never raw values, never `space[N]` directly.

| Token (CSS var) | Resolves to | Usage in this block |
|-------|-------|-------|
| `--space-section-y-lg` | 128px | `Section` vertical rhythm (source `.ccx padding: clamp(72,8vw,128px)` → `lg`) |
| `--space-section-y-md` | 96px | Section vertical rhythm under 768px (responsive step-down) |
| `--space-stack-loose` | 24px (`space[5]`) | Editorial header rhythm (eyebrow→heading→lead); source `.ccx__head gap: clamp(16,1.6vw,22px)` → `loose` |
| `--space-content-gap` | 32px (`space[6]`) | Header block → rail gap (source `.ccx__head margin-bottom: clamp(36,4vw,56px)`); rail → controls gap (source `.ccx__controls margin-top: clamp(24,2.4vw,34px)`) |
| `--space-stack-default` | 16px (`space[4]`) | Track gap between cards (source `.ccx__track gap: clamp(16,1.5vw,22px)` → `default`); card caption internal gap (source `.ccx__cap gap: 9px` → snap to 16px reads premium, or `--space-stack-snug` 12px if tighter is wanted) |
| `--space-stack-snug` | 12px (`space[3]`) | Card caption internal gap (alternative to `default` — source `gap: 9px`) and card inner padding inset |
| `--space-inline-default` | 8px | "Read more" label → arrow gap (source `.ccx__more gap: 6px`); dot-to-dot gap (source `.ccx__dots gap: 9px` → 8px token) |
| `--space-5` / `--space-3` | 24px / 12px | Card caption inset from card edges (source `.ccx__cap left/right/bottom: clamp(16–24px)`) |
| `--space-4` | 20px | Control row gap between dots cluster and nav cluster (source `.ccx__controls gap: var(--space-4,20px)`) |
| `--space-container-pad-{sm,md,lg}` | 16 / 32 / 64px | Responsive horizontal padding (via Container) — source `.ccx__wrap` is `92vw` capped at 1280px |

Card **dimensions** (size + radius) are *not* spacing-scale values; they are layout values expressed with `clamp()` + `calc(var(--radius-lg) * N)` in block-local CSS (see Interaction Notes). The 8-point scale governs gaps/padding/rhythm only.

Exceptions: **none.** All gaps/padding/rhythm flow through existing semantic space tokens. The source's `clamp()` fluid spacing collapses to discrete DS tokens with sm/md/lg responsive steps — the faithful DS-native expression.

> **Card-title note (flagged for planner):** the source card title is **display-family ultrabold** at ~`fs-xl`. The DS `h3` role is **body-family weight 400** at `--fs-xl`; the DS `h2` role is **display-family weight 800** at `--fs-2xl` (one step larger). To stay faithful to the source's bold display card title *and* honor the role system, the recommended mapping is **`Text role="h2" as="span"`** with a block-local `font-size` clamp down toward `--fs-xl` if `--fs-2xl` reads too large in the card — OR keep `role="h3"` for the lighter editorial look. **Recommendation: `role="h3" as="span"`** (cleaner, lighter, premium-editorial; the bold display card title is a deck-fan-era flourish). Either way **weights stay exactly 2 (400 + 800)** — do not introduce weight 600 from the source `.ccx__more`.

**Weights used: exactly 2** — 400 (body) + 800 (display ultrabold). Matches the DS font set (no 500/600 exists). The generic "3–4 sizes / 2 weights" heuristic is superseded by the DS's role-based type scale (the project's binding type contract; same rationale as Phases 1–2). The source's `font-weight: 600` on `.ccx__more` is **dropped** (no 600 in the font set) — the affordance reads via color + the arrow icon instead.

Measure constraints (from source, preserved on block-local wrappers): heading `max-width: ~60ch` header column + `text-wrap: balance`; lead `max-width: 54ch` + `text-wrap: pretty`; card description `text-wrap: pretty`.

## Color (no new palette — REQ-02)

The block carries its own theme via `Section theme`. Default **`yellow`** — the existing theme whose `surface-page` is `palette.yellow[200]`, matching the source `--ccx-yellow #FFFD8C`. **No raw hex anywhere** (Stylelint enforced). The source's inline `--ccx-*` literals map cleanly:

| Source literal | DS equivalent (no new token) |
|---|---|
| `--ccx-yellow #FFFD8C` (page) | `yellow` theme `--color-surface-page` (= `yellow[200]`) |
| `--ccx-ink #433535` (heading/lead text) | `--color-text-default` (= `neutral[800]` in `yellow` theme) — AA-safe on yellow (theme passes the contrast gate) |
| `--ccx-deep #230800` (active dot, nav buttons) | `--color-text-default` (the dark ink) — used as the dot/nav-button ground |
| `--ccx-paper #FFFEF2` (card caption text) | `--color-text-on-dark` (= `#FFFEF2` exactly — already a semantic token) |
| `--ccx-yellow` on "Read more" | `--color-text-on-dark` or a token tint — keep it light-on-dark; do **not** introduce a new accent |

Within the `yellow` theme the 60/30/10 reads as:

## Interaction & Accessibility Notes (SC#2 — the binding success criterion)

- **Scroll-snap rail:** `<ul className={s.rail}>` with `overflow-x:auto`, `scroll-snap-type: x mandatory`, hidden scrollbar; `tabIndex={0}` so the region is keyboard-focusable for native arrow-key scrolling; `aria-label="{heading} — scrollable cards"` so AT announces a labelled scroll region. Implicit `role="list"`; each card in an `<li>`.
- **Cards:** when `card.href` → render `<a href className={s.card}>` (a real navigable link, natural tab stop, `Enter` activates); when no `href` → render a non-interactive `<article className={s.card}>` (no `tabIndex`, no dead click). Card size `flex: 0 0 clamp(258px, 23vw, 310px)`; height `clamp(366px, 31vw, 420px)`; under 560px `flex-basis: 78vw; height: 104vw` (source). Radius `border-radius: calc(var(--radius-lg) * 1.5)` ≈ 24px (source `clamp(18–26px)`), `overflow: clip`. Image fills via `object-fit: cover`, `focalPoint="center"`, `loading="lazy"`.
- **Dot navigation — NOT a tablist (D-2):** author as a `<nav aria-label="Crash course pagination">` containing a `<button>` per card with `aria-current={i===activeIndex ? 'true' : undefined}` and `aria-label="Go to {card title}"`. The active dot widens to a pill (`width: var(--space-7)` ≈ 48px when active vs a small square otherwise) and uses `--color-text-default`. **Rationale:** the source used `role="tablist"`, but the cards are not `tabpanel`s (they're a scroll region) — a tablist would make AT promise tab semantics that don't exist. A labelled scroll region + `aria-current` buttons is the honest, `NeighborhoodPaginator`-proven pattern.
- **Prev / next:** two round `<button>`s, `aria-label="Previous"` / `"Next"`, `disabled` at the respective ends, block-local inline chevron SVG (`aria-hidden`, `focusable="false"`). On click: `scrollToIndex(activeIndex ∓ 1)`.
- **Keyboard control (SC#2):** (1) cards are natural tab stops and activate with `Enter`; (2) the rail region (`tabIndex=0`) scrolls with native `ArrowLeft`/`ArrowRight` when focused — additionally wire an `onKeyDown` on the rail so `ArrowLeft`/`ArrowRight` call `scrollToIndex(activeIndex ∓ 1)` for snap-aligned movement, `Home`/`End` jump to first/last (progressive enhancement, restrained); (3) dots + prev/next are buttons, fully keyboard-operable. **Focus order:** header → rail (then each card in DOM order) → dots → prev → next. Visible focus on every interactive element via the global token focus ring (`--color-focus-ring`, 2px offset).
- **Accessibility — Section labelling:** `aria-label={heading}` on the `Section` (`Text` exposes no `id`, so `aria-labelledby` is not wired — Phase 1/2 precedent). Heading renders as `<h2>` (source `.ccx__title` is an `h2`). Card titles are spans inside interactive cards (not document headings — keeps heading outline clean).
- **Reduced motion:** rail fully scrollable, all cards visible, `scrollToIndex` instant. No entrance, no hover transforms.
